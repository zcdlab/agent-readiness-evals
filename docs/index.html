Harness Engineering is the discipline of building the environment, sandbox constraints, and deterministic verification gates that transform stochastic LLMs into high-assurance autonomous software engineers.

The 4 Foundations of Harness Engineering

How deterministic execution loops and blast-radius barriers tame stochastic coding agents.

🔄

The Deterministic Verification Loop (Red → Green → Refactor)

TDD Feedback Gate

Without an automated harness, stochastic LLMs hallucinate success. An Agent-Ready harness enforces a strict four-stage loop before any code change is accepted:

1. RED (Reproduce)

Write minimal failing test in tests/ proving the defect or requirement.

2. GREEN (Patch)

Apply minimal surgical patch in src/ (<60 LOC). Execute targeted test.

3. REFACTOR & LINT

Run static type checking (mypy) and code style linters (ruff).

4. VERIFICATION GATE

Run full regression suite (pytest -v, budget <5s). Block on any failure.

🪜

Differentiated Verification: The 5-Tier Testing Ladder

Multi-Tier Harness

High-assurance agent harnesses do not rely on a single binary test check. They provide differentiated verification layers matching the agent's task phase:

Tier 1: Fast Unit
< 0.2s budget
Single function loop via pytest -k
Tier 2: Static Types
< 1.0s budget
Strict mypy & ruff linting
Tier 3: Invariants
< 0.5s budget
Idempotency & state fsm tests
Tier 4: Regression
< 5.0s budget
Full suite 100% green gate
Tier 5: Telemetry

Side-by-Side Comparison

Readiness Pillar ❌ Unprepared Repo (Outage Risk) ✅ Agent-Ready Repo (Safe Autonomy)
🛡️ Blast-Radius Boundaries
25 Points
 Zero boundary control: Agent has unrestricted write access to infra/prod/, .env, and database migrations. Accidental destruction of cloud resources. Zero-trust policy (.agent-policy.yaml): Restricts agent permissions to sandbox_write. Quarantines production infra and secrets behind cryptographic human approval tokens.
🤖 Agent Operating Contract
25 Points
 Missing guidelines & architecture: Agent guesses conventions, violates layer boundaries, invents invalid build steps, and wastes tokens exploring dead paths. Explicit Contract (AGENTS.md): Anchored in ARCHITECTURE.md and DESIGN.md. Declares build stack, test commands, code conventions, and permission tier boundaries.
🧪 Deterministic Verification
25 Points
 No automated test suite: The agent cannot self-verify changes. Generates code that appears visually correct to an LLM but fails at runtime with syntax or logic errors. Automated Test Harness (tests/): Fast local test suite (pytest, jest). Agent follows test-driven development: generates test, implements code, self-heals failures before commit.
⚙️ Reproducible Build Specs
25 Points
 Unpinned scripts: No pyproject.toml or lockfile. Agent attempts random pip installs or breaks system python environments. Pinned Build Definitions: Explicit pyproject.toml or BUILD.bazel specifying exact dependencies and reproducible virtual environments.
